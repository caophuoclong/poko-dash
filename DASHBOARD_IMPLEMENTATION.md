## 🎨 Design Principles

### Visual Hierarchy

1. **Summary first** - 6 KPI cards at the top
2. **Status second** - Pipeline snapshot grid
3. **Trends third** - Time series charts
4. **Actions fourth** - Attention items & schedule
5. **Details last** - Category/platform breakdowns

### Dark SaaS Aesthetic

- Serious, premium, operational feel
- Uses existing design tokens (frost, surface, accent-orange, etc.)
- Compact but readable typography
- Subtle borders and backgrounds
- Color-coded badges for status

### Responsive Layout

- **Mobile**: 2-column cards, stacked sections
- **Tablet**: 3-column cards, 2-column layout
- **Desktop**: 6-column cards, full grid layouts

## 🔧 Technical Details

### No External Dependencies Added

- Used pure SVG for sparkline charts (no recharts/visx)
- Kept bundle size minimal
- All animations via Tailwind utilities

### API Pattern

```typescript
GET /dashboard/overview?range=7d|30d|90d

Response: DashboardOverviewResponse {
  summaryCards: [...],
  pipelineSnapshot: [...],
  trendSeries: { postsGenerated, postsPublished, seedsApproved },
  attentionItems: [...],
  upcomingSchedule: [...],
  topBreakdowns: { categories, platforms, topSeeds }
}
```

### State Management

- **Loading**: Skeleton with matching layout
- **Error**: Full-page empty state with retry
- **Empty**: Onboarding CTA to create first seed
- **Success**: Full dashboard with all sections

Includes realistic mock data generator for:

- Previewing dashboard before backend ready

## 📝 To-Do: Backend Implementation

When implementing `GET /dashboard/overview`:

1. **Aggregate metrics** across time range
2. **Calculate pipeline counts** from database
3. **Generate daily trend series** (group by date)
4. **Identify attention items**:
   - `SELECT seeds WHERE status='approved' AND products=[]`
   - `SELECT jobs WHERE status='failed'`
   - `SELECT seeds WHERE approved_at < NOW() - 7 days AND post_count = 0`
5. **Query next 5 scheduled posts** ordered by `scheduled_at`
6. **Compute top breakdowns**:
   - `SELECT category, COUNT(*) ... GROUP BY category ORDER BY count DESC LIMIT 5`
   - Similar for platforms and seeds

### Performance Tips

- Cache results for 1 minute (hook already configured)
- Use database indexes on `status`, `created_at`, `scheduled_at`
- Pre-aggregate metrics in background job if dataset is large
- Consider materialized views for complex queries

## 🎨 Design Choices Explained

**Why 6 summary cards?**
Balances density with clarity. Covers core KPIs without overwhelming.

**Why lightweight SVG charts?**
No bundle bloat, fast rendering, sufficient for overview. Can upgrade later.

**Why modular components?**
Easy testing, reusability, clear separation of concerns.

**Why attention section?**
Operational dashboards should surface actionable items, not just metrics.

**Why limit schedule to 5?**
Focus on immediate priorities. Full schedule on dedicated page.

**Why 3 range options?**
Covers: recent (7d), monthly review (30d), quarterly trends (90d).
